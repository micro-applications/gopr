# GoPR Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Godiff into GoPR: one window whose sidebar is a GitHub PR inbox (my PRs, then PRs waiting on my review, filtered by org and by 7/30 days), with a PR workspace on the right that has full-file tabs and Markdown preview.

**Architecture:** The existing `window` (`window.go:53`) stays the app's one state object; it already switches sources (`setSource`/`switchTo`). It gains the ability to start with no repository and to rebind to another repository (`bindRepo`) when an inbox PR from another repo is chosen. The inbox is new state on `window` plus new GitHub search calls in `internal/github`. The PR's file tree moves from the window sidebar into a pane inside the workspace. Local-mode UI (History, commit, branch compare, the per-repo PR list, per-repo windows) is removed; the loading code for working-tree and commit sources stays because the diff-rendering tests use it.

**Tech Stack:** Go 1.27, MyGo UI (`github.com/egoist/mygo/ui`, `ui/markdown`), GitHub GraphQL search, git CLI.

**Spec:** `docs/superpowers/specs/2026-11-12-github-pr-reviewer-design.md`

## Global Constraints

- App name `GoPR`; command `gopr`; bundle identifier `dev.egoist.gopr`. Go module path stays `github.com/egoist/godiff`.
- Settings file `~/.gopr/gopr.jsonc`, copied once from `~/.godiff/godiff.jsonc` when the new file doesn't exist. Store `state.json` in MyGo's user-data dir (`os.UserConfigDir()/GoPR`, which follows `mygo.App.SetName`), copied once from the sibling `Godiff` dir.
- Inbox sections, in order: "My pull requests", "Waiting on my review".
- Period menu values: 7 and 30 days only; default 7; filters on created date; applies to both sections.
- Org menu: the viewer's orgs plus the viewer's own login; default all checked.
- Search cap: 100 per section; a capped or failed section says so.
- Clone root setting `cloneRoot`, default `~/Projects`; clones go to `<cloneRoot>/<owner>/<name>`.
- Never check out, reset, or otherwise touch a clone's work tree; only fetch (as `fetchPull` does today) and `git clone`.
- **`w.repo` is read only on the main thread.** Background work (`load`, `fetchPull`, `loadContents`, analysis) captures `repo := w.repo` before it starts and uses that value; results check `w.stale(gen)` and are dropped when stale. This matters once `bindRepo` can replace `w.repo` mid-load.
- `githubToken()` runs `gh`; call it only off the main thread (inside `background`).
- Refresh the inbox on window focus when older than 5 minutes, on the refresh button, and on ⌘R. No polling timer.
- Markdown extensions: `.md`, `.markdown`, `.mdx` (case-insensitive).
- Views are tested without a window via `ui.NewTester` (`Find` returns a `Rect`; `Menu`/`ChooseMenuItem` drive menus; `OpenedURLs` records opened links). GitHub is faked with `httptest` (`fakeGitHub` in `pull_test.go`, and the one in `internal/github/github_test.go`). Every new test that touches the store calls `freshState(t)` (Task 3).
- Each task ends with `go test ./...` green; Tasks 4 onward also run `go test -race ./...`.

## Review Focus

1. **Choosing a second PR while the first is still cloning or fetching, including one in another repository:** the last choice wins; the earlier one's results are dropped and never fetched into the other clone. Tests: Task 4 `TestOpenPullLastChoiceWins`, `TestSwitchRepoDuringFetch`.
2. **`<cloneRoot>/<owner>/<name>` exists but is not a clone of that repo:** clone fails with a clear error and never overwrites. Test: Task 3 `TestCloneRepoRefusesExistingDir`.
3. **Saved clone path moved or deleted:** the locator falls back to recents and the scan instead of erroring. Test: Task 3 `TestLocateCloneDropsStalePath`.
4. **Token missing or rejected (401):** the window shows the sign-in state, or the inbox shows the error with Try Again. Tests: Task 6 `TestInboxSignedOut`, `TestInboxError`.
5. **Every org unchecked:** the inbox shows "No organizations selected" and sends no search. Test: Task 6 `TestInboxNoOrgs`.
